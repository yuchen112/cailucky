CxQ Fairy-tale Richman — testing branch 20260912-2200

Release status
- This build belongs only to preview/cxq-fairytale-richman-testing.
- The main branch remains unchanged until the user approves this testing build.
- Runtime remains one integrated path: index.html -> core.js + viewport.js + game.js.

Streamlined game design
- The in-match card book, tool box, shop, minigames, coupons, bank, hospital and police systems are removed from the playable route.
- Character setup now leads to a dedicated two-slot persistent-equipment phase. Equipment is selected before the map and remains automatic for the whole match.
- Eight independently generated equipment assets cover property, construction, fortune, defense, income and movement effects.
- Random events now affect cash, land, buildings, movement or protection only. AI outcomes always pause for the player to acknowledge.
- Roaming gods move on the road, attach only when a player finishes movement on the same node, replace an existing companion cleanly, and never spawn the Death God normally.

Property and presentation
- Every land node has a road coordinate for pawns and a separate authored roadside plot coordinate for buildings.
- Ownership is shown by player-color rings, portrait plaques and P-number, while pawns remain on the road node.
- Buildings progress through five levels. Lv5 uses the landowner character's dedicated landmark artwork.
- The HUD shows cash, net worth, land, building count, equipment and god status without card/tool/bank clutter.
- Player details use Overview, Property, Equipment and Status tabs with all content contained inside the artwork frame.
- Dice use six physical face assets, a minimum thirty-frame throw/settle sequence and an explicit rolled-total-to-final-step message.
- Character movement uses two walking poses and at least thirty frames per tile.

Compatibility and verification
- The 1600x900 safe playfield stays proportional; extra-wide landscape space is filled with the current scene backdrop.
- Dynamic mobile browser bars, safe-area insets, Safari/PWA caching and mouse/touch coordinate mapping share the same viewport adapter.
- Saves migrate to the equipment model while removing obsolete inventories and facilities.
- Automated checks cover asset/PWA parity, equipment rules, event art, gods, dice adjustments, land/building economics, saves, layout bounds and full-match simulations on all three maps.
- Browser QA covers home, character selection, equipment, map, rules, live board, purchase, AI acknowledgement, player data, mobile landscape and ultrawide landscape.
