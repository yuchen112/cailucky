# 心光對決街機版驗收紀錄

版本：20261007-arcade3。

載入優化：主選單只下載一個 395,931 bytes 素材包，內含八張獨立圖；選角另下載一個 424,767 bytes 素材包；森芽對鈴可的新對戰在已選角後下載四包，合計 1,224,396 bytes。重新對戰直接重用已解碼的圖。全部 170 張實際遊戲圖像重新編碼至適合畫面顯示的尺寸，透明度與寬高比例保持一致，下載量從 16,515,588 降為 5,211,482 bytes（約減少 68%）。這是完整獨立圖片的二進位封裝，不是合圖、裁切或 sprite sheet。原始素材與提示詞仍保留。

`node tools/test-arcade-packs.mjs` 確認 170 張圖像全部可解碼、透明度与比例保持、十角色與四場地素材索引完整，並驗證首次選單一個請求、選角一個請求、對戰四個請求、並行去重、再次對戰不重新請求、損壞素材包拒絕與可重試。DOM 介面直接共用素材包解碼後的 Blob 圖片，不再另外下載單張原圖。載入畫面顯示已下載 KB，單包超過 60 秒可回報錯誤，避免無期限等待。

十位角色均保留正式名稱與既有身份，每人新增十張獨立動作美術，搭配既有獨立待機、技能與勝利素材。共 128 張本次生成素材，包含 100 張角色動作、26 張介面／特效／背景及兩張分別生成的橫向封面與方形縮圖。manifest 記錄全部素材及既有 30 張姿態來源；prompts、cover-prompts 與 asset-plan 保留生成提示詞。整張素材縮放與透明邊界定位，沒有合集裁切、網格切片變形或 CSS 角色繪圖。動作由獨立關鍵姿態與時間線組合，並非每秒生成 60 張不同圖。

遊戲以 60Hz 固定步進運算，畫面按 requestAnimationFrame 繪製，低效能時降低畫布解析度。全流程使用 1280×720 橫向舞台，直向顯示旋轉提示並暂停對戰。CSS 用於位置、文字、可操作狀態和版面，角色、框體、按鈕及場景均使用圖像。

正式首次載入檢查發現全角色同時預載等待過長，已改成啟動先載入 28 項選單與選角素材；開始對战後才載入當場兩位角色的完整姿態、操作介面與該場景，重複使用已解碼的素材，不預載無關角色的動作。準備期間不推進回合或接受對戰輸入，下一場狀態先保存，載入失敗可回主選單重試。分批載入後已在瀏覽器實際確認米洛對森芽開始對戰、反擊示範造成 125 傷害、約 75 FPS，沒有 console 錯誤。

`node tools/test-heartlight-arcade.mjs --assets`：23 項整合檢查通過，涵蓋十角色與故事旅程、有效攻擊幀與距離、下段／跳攻／正面格擋／投技、真實三段連招、技能差異、必殺能量、倒地起身保護、AI 出招間隔、訓練示範、生命繼承、完整對戰狀態存檔、舊存檔遷移與損壞備份拒絕、全部独立素材。

實際瀏覽器 UI 驗收：主選單與十角色選角、四場景與三難度；訓練三段連招與觸控重攻命中；自由對戰 AI 實際攻擊；雙人 J 與數字鍵盤 1 分別造成 62、67 傷害；故事第二場續關與第五場專屬結局；生存第五勝 500 生命回復到 620 並帶入下一場；舊備份恢復 777 生命／42 能量；損壞備份拒絕；自訂鍵位 J 改成 H；文字備份匯出與還原；JSON 檔案匯入。

667×375 手機橫向視窗與 375×667 直向旋轉提示實測。發現並修正焦點引發容器捲動，攻擊前後六個操作按鈕座標保持一致，容器 scrollTop 為 0。設定、訓練與備份面板內容高度不超出 560。回復橫向後需繼續對戰，存檔重載能續玩。

上述瀏覽器自由／訓練對戰顯示約 72–75 FPS；這是該瀏覽器環境的量測，不能推定所有手機均超過 40 FPS。尚未以實體 iPhone／Android 或實體手把驗收。手把程式提供兩支控制器映射，雙人鍵盤已實測。

JSON 下載按鈕已提供標準 Blob 下載，但內建瀏覽器未回報 download 事件，因此未把檔案落地下載列為通過；另提供完整可選取的備份文字，其格式與還原已確認。音樂來源沿用既有授權音訊，瀏覽器仍須第一次互動才能啟用音訊。

對戰存檔使用新儲存鍵並保留舊版資料；資料格式延續原備份格式。網站 data/app.json 位置與其他遊戲保持原有設定。
